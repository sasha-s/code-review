# Pipeline v1 experiment - 2026-07-17

This note covers the isolated pipeline experiment under
`experiments/review-lab/pipeline_v1.py`. It does not modify the global
`deepreview` skill.

## Setup

- Pipeline v1.0:
  - planner -> broad v7 reviewer -> focused v8 subpass -> verifier ->
    challenger -> synthesis.
  - Result on `discourse-commit-4f8aed295a`: `0/6`.
  - Failure mode: the verifier over-pruned source-backed boundary concerns and
    the challenger did not restore browser/template/nil-receiver issues.
- Pipeline v1.1:
  - planner -> fixed cluster v7 reviewers:
    browser/render, remote/import, persistence/tests -> focused v8 subpass ->
    verifier -> challenger -> synthesis.
  - Cache key includes pipeline version, model, worktree HEAD, blind input-file
    hashes, prompt hash, and previous-stage output hashes.
  - All child reviewer and judge event scans below reported `hit_count=0`.
- Pipeline v1.2:
  - Adds generic controller CRUD nil-record checks, normalization parity checks,
    and a final compound-failure audit.
  - Tested on `discourse-commit-d1c69189f3`; it changed which goldens were hit
    but did not improve total recall.

## Observations

- The cluster split is useful. On `4f8aed295a`, browser/render recovered invalid
  ERB and `postMessage`; remote/import recovered the fetch guard gap; challenger
  restored the standalone asset issue and narrowed the remote-fetch claim.
- Verifier policy matters more than more checklist text. v1.0 found plausible
  candidates but deleted too many because exploit proof was incomplete. v1.1
  keeps source-backed API/security/renderability mismatches as boundary concerns.
- Stage artifacts are useful for failure analysis. `d1c69189f3` shows the
  planner and cluster reviewers touched the right areas, but the final miss came
  from introduced-vs-preexisting adjudication and not-found CRUD not being
  promoted.
- This is still fixed-lens clustering, not dynamic fan-out from parsed planner
  JSON. It approximates cluster review without making the runner brittle.
- v1.2 shows that adding generic checks can trade recall between issue classes.
  The CRUD prompt recovered missing-record handling, but stochastic stage output
  or prompt focus lost callback nil-mutation wording on the same case.

## Remaining Failure Modes

- Compound benchmark rows are brittle. v1.1 found unescaped URL XSS but did not
  state the nil `contents <<` crash in the same final finding, so the judge
  marked the compound row missed.
- Introduced-vs-preexisting strictness can reduce benchmark recall. The
  `record_for_host` mixed-case issue was rejected because old comparison was also
  case-sensitive, while the benchmark expected the changed lookup contract to be
  reported.
- Admin CRUD not-found handling needs a more generic controller-action contract
  check: `find_by_id`/lookup returning nil followed by update/destroy/method calls
  should survive at least as a boundary concern when the endpoint is newly added.
- The synthesis can over-include useful adjacent findings such as asset
  precompile and raw HTML body import. Those are review-useful but do not improve
  golden recall.

## Next

- Keep the generic controller CRUD/not-found check, but add callback mutation
  checks for `before_validation`/normalization methods that call mutating string
  APIs on params/model fields before presence validation.
- Strengthen the final compound-failure audit so nil/type receiver issues remain
  visible when another nearby normalization or escaping issue is also reported.
- Consider a dynamic planner JSON schema later, but keep v1.1 fixed-lens
  clustering until it has more subset data; v1.2 should be treated as
  experimental until it is tested on more cases.
