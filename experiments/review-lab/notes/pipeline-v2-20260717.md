# Pipeline v2 experiment - 2026-07-17

Pipeline v2 is isolated under `experiments/review-lab/` and does not modify the
global `deepreview` skill.

Repro note: v2.2 is preserved as `pipeline_v2_2.py` with prompts under
`prompts/pipeline-v2/`. v2.3 uses `pipeline_v2.py` with prompts under
`prompts/pipeline-v2.3/`. Later variants are preserved as separate wrappers and
prompt dirs rather than replacing the global skill or the v2.2 baseline.

## Design Change

v1 was still prompt/checklist shaped. It improved recall on some classes but
could trade one miss for another because candidates were only prose.

v2 changes the unit of work:

- `contract-planner`: emits stable `C-###` contract cards and `K-###` candidate
  seeds generated from changed operations.
- focused ledger reviewers: update cards/candidates instead of writing standalone
  review prose.
- `hole-finder`: audits uncovered contracts and dropped candidates.
- `evidence-verifier`: assigns a disposition to every carried candidate.
- `transition-challenger`: audits stage transitions and restores weakly dropped
  candidates.
- synthesis: writes the final review from the ledger.

v2.2 tightened three generic failure modes seen in v2.0/v2.1:

- split known API producer argument grammar from receiver validation
- compare platform security protection against replacement application guards
- keep exact suspicious template/generated-code syntax as a finding or boundary
  concern unless a syntax/render check proves it valid

## What Improved

- On `4f8aed295a`, v2.2 recovered every expected class in a single final review:
  `open(url)` sink validation, substring origin check, full-referrer
  `postMessage` targetOrigin, `X-Frame-Options: ALLOWALL` with referer guard,
  nil/non-mutable import content plus unescaped URL interpolation, and invalid
  ERB.
- On `d1c69189f3`, v2.2 recovered callback nil mutation, admin update/delete
  missing-record handling, and case/port lookup canonicalization in one run.
- On the second source-backed batch, v2.2 recovered all four previously missed
  classes: flex/float fallback, SCSS light-branch inversion, lazy locale
  thread-safety/string-vs-symbol normalization, and `gifsicle --resize-fit 80%`.
- The stage artifacts now explain misses better: when a candidate is lost, the
  hole finder and transition challenger usually show the exact broad contract or
  weak rejection that caused it.
- `ledger_check.py` now gives an evaluator-independent continuity view. The
  second batch had zero contract/candidate drops from planner through synthesis.
- The cross-repo slice surfaced a useful union-only improvement: `grafana-79265`
  now has a hit for the time-window inconsistency, while still preserving the
  source-backed rejection of the invalid `Exec(args...)` golden.
- v2.3's new resource/locale ledger fixed Keycloak contract continuity and
  recovered the zh_CN script issue, but did not recover the sanitizer matcher or
  typo findings and regressed Grafana. Keep v2.2 as the stronger experimental
  baseline for now.
- v2.4 avoids the Grafana regression from v2.3, but it still adds no unique
  benchmark hits and has two trade cases. The limiting problem is not only
  coverage; it is stable prioritization of multiple verified issue classes.
- v2.5 shows that structured carry tables alone do not fix the pipeline if the
  verifier/challenger assigns weak dispositions. On `grafana-79265`, continuity
  was clean but real issues were carried as gaps rather than findings.
- The `grafana-79265` v2.5 trace shows the exact verifier failure:
  count-then-insert race stayed an unverified `C-006` gap, `RowsAffected` was
  framed as cross-driver unchanged-row semantics rather than missing-device
  denial, and the timestamp-window mismatch was rejected because production
  `TagDevice` sets `UpdatedAt` with `time.Now()`.
- v2.6 only partially fixes that calibration problem. Its three-case trade slice
  scored `8/14` against `9/14` for the best prior runs, with zero unique hits.
  The misses are now mostly exact consequence and branch-state wording rather
  than raw coverage: Cal.com computes the Zod schema wrongly but fails to state
  the runtime schema error, Grafana sees affected-row/timestamp hazards without
  matching the missing-device/window consequences, and Keycloak discusses anchor
  strictness without enumerating the translated-anchor matcher-group failure.
- v2.7 is the first consequence-decomposition win: it raised the best-single
  aggregate by one by scoring Cal.com `5/5`. It did not improve the three-case
  slice overall because Grafana still traded between consequence classes and
  Keycloak still missed the exact extra-anchor matcher branch.
- v2.8 is a negative result. Adding more generic sentinel/time/matcher rules
  produced plausible adjacent findings, but selection became less stable:
  Cal.com lost the Zod runtime-error framing, Grafana shifted from zero-row to
  time-window credit while still missing auth-denial, and Keycloak found the
  omitted-anchor direction instead of the extra-anchor matcher-group direction.
  It also produced a Keycloak continuity flag for a verified dependency/classpath
  candidate missing from synthesis.
- v2.9 is a mixed but useful result. The selector fixed the biggest tradeoff
  case by raising `grafana-79265` from prior best `3/5` to `4/5`, but it did not
  add new union coverage: Cal.com regressed from v2.7's `5/5`, and Keycloak
  still needs better branch enumeration rather than stronger final selection.
- v2.10 is a negative result. A separate branch/consequence auditor added cost
  and changed which sibling candidates survived, but did not improve union or
  best recall. The useful lesson is that branch enumeration must be coupled to
  selection pressure and candidate preservation; a standalone audit becomes
  another prose artifact the selector can still trade away.

## Remaining Issues

- `d1c69189f3` still misses the migration-normalization golden in the single
  v2.2 run, even though v2.0 hit it and union across v2 attempts is `4/4`.
  v2.2 focused the migration discussion on raw SQL interpolation/quoting and did
  not state the distinct raw-migrated-value-vs-bare-host lookup failure.
- v2.2 is noisier than v1: it finds more source-backed adjacent issues, some of
  which are real review value but not benchmark goldens.
- Contract ids are still markdown, not machine-validated JSON. That is enough
  for transition auditing, but not enough to enforce that every candidate id is
  carried programmatically.
- The `4f8aed295a` continuity check found candidate alias drift
  (`K-new-001(browser)` vs paired synthesis ids). The underlying finding was
  present, but exact markdown ids are not stable enough to be a hard gate.
- Judge table parsing must avoid treating numbers inside descriptive golden
  labels as ids. This is now fixed by requiring explicit `G1`/`1`/`Golden 1`
  cells; otherwise table rows are numbered by order.
- `cal_dot_com-11059` shows single-run issue-class tradeoff: v2.2 carried all
  candidate ids to synthesis but prioritized away the hardcoded
  `refresh_token: "refresh_token"` fallback while recovering the computed Zod-key
  problem. Continuity alone cannot catch prioritization drops.
- `grafana-79265` shows a real transition drop: `K-new-001` was verified but not
  synthesized. The final review still tied prior best, but the checker correctly
  flagged lost candidate evidence.
- `keycloak-37429` shows domain coverage weakness: candidate ids were preserved,
  but resource/locale contracts `C-004` through `C-007` dropped from synthesis
  and v2.2 missed Simplified Chinese terminology, translated-anchor matcher
  alignment, and the `santizeAnchors` typo.

## Next

- Add an evaluator-side report of single-run best vs union so prompt iterations
  that trade issue classes are visible immediately.
- Keep testing v2.2 on the remaining source-backed miss subset before promoting
  it over v7 as the default experiment.
- Consider making ledger artifacts structured JSON in addition to markdown so
  continuity can be enforced without alias false positives.
- Keep v2.9 as the current best single-run trade-slice variant, but do not
  promote it without reducing extra finding noise and recovering v2.7's Cal.com
  Zod consequence framing.
- Do not promote v2.10. If executable micro-checks are added, attach their
  observed result directly to the candidate disposition instead of adding a
  separate late prose audit.
- Avoid adding focus stages without a prioritization budget; v2.3 improved
  continuity but appears to dilute high-value state/API findings on Grafana.
- Next pipeline change should merge branch enumeration into the selector schema:
  one candidate can have multiple source-checked branch records, and every
  source-backed branch above low severity must be selected, merged by exact root
  cause, or rejected by a branch-specific source fact.
- The adversarial step should attack weak rejections directly: for each rejected
  or gap-labeled candidate, require the rejecting source fact, the exact branch
  it applies to, and a check that sibling consequences were not rejected by a
  source fact for a different branch.
